# Release 0.2.0

- Intent: Publish yach 0.2.0 to crates.io, so `cargo install yach` gets the
  roughly 80 feature and fix PRs merged since 0.1.0 (2026-07-27). Close the
  gaps that make a public release worse than it should be first.
- Constraints:
  - `just release-check` and its Rig probe stay as strict as they are. The
    release removes the vendored `rig-core` from the publish path; it does not
    relax the check.
  - Existing sessions, stored connections and ChatGPT logins keep working
    across the Rig change, or migrate through a tested path.
  - Review-first stays the default approval mode (CEW-164 adds auto-run of
    read-only commands inside it, nothing broader).
  - The release does not wait on the M1 dogfood gate (CEW-147). It is a
    release of work already on `main`, not a milestone claim.
- Decisions:
  - crates.io is the release channel, after the vendored Rig is gone; no
    interim GitHub-only release (you)
  - Version 0.2.0: minor bump for features plus CLI, protocol and persistence
    changes, per the README's pre-1.0 rule (you)
  - Scope beyond `main`: wvbm, release-profile size slice, CHANGELOG, CEW-164
    first slice, flaky RSS test, flake dev shell removal (you)
  - Rig: decide between migrating to registry 0.46 with patches upstreamed and
    a yach-owned published rig crate only after compiling against 0.46; a
    published owned crate is the fallback if upstream timing would hold the
    release more than a few weeks (agent default)
  - CEW-164 ships its first slice only: the fail-closed read-only classifier
    inside `review` and an honest auto-review status. Persistent or prefix
    command rules stay out. It needs its spec approved before implementation
    (agent default)
  - No prebuilt binaries in this release; the GitHub release carries the
    CHANGELOG section, as 0.1.0 did (agent default)
  - The CHANGELOG is written once from history and reconciled with `main` at
    the cut, not maintained per PR during this milestone (agent default)
- Milestones:
  - 0.2.0 release, in order:
    1. CEW-454 Rig reconciliation and decision (critical path; starts first)
    2. In parallel with 1, each small: CEW-459 gateway unknown-model
       classification, CEW-460 flaky RSS test, CEW-425 flake dev shell,
       CEW-457 release profile
    3. CEW-164 approval default, first slice (medium: spec, then plan)
    4. CEW-455 remove vendored rig-core from the publish path (after 1)
    5. CEW-456 CHANGELOG (after 3 and 4, so its notes cover them)
    6. CEW-458 cut and publish 0.2.0 (blocked by all of the above)
- Roadmap: https://linear.app/cewlabs/project/yach-13cd617abaec, milestone
  "0.2.0 release"
- Thread: CEW-458
- Approval: waiting

## Risks

- **Rig is the long pole.** The vendor carries about 3,700 changed lines over
  rig-core 0.41.0. Upstream 0.46 now has a `chatgpt` provider and caller-built
  Responses input, but a text search found no expected-account check,
  auth-file lock or Codex `client_version`. Until CEW-454 compiles yach against
  0.46, the size of CEW-455 is unknown.
- **CEW-164 is the largest scope item** and the only one that changes default
  behavior. If its spec review slips, the release waits for it unless the
  operator drops it from the milestone.
- **Session persistence.** Rig 0.42 made `AssistantContent` type-tagged and
  incompatible with 0.41-persisted content. CEW-454 must say whether yach
  persists Rig types before CEW-455 starts.
