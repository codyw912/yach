## Corrections to the 2026-08-24 baseline

1. **Claude Code's default is now `auto`, not a conservative mode.** Docs: since v2.1.283 "auto mode is the built-in starting permission mode for interactive terminal and VS Code sessions" on all plans/providers (https://code.claude.com/docs/en/permission-modes). The changelog files the same line under 2.1.284 (CHANGELOG.md:497), so treat the exact version as 2.1.283/284 [INFERENCE: docs vs changelog disagree by one]. Before that, auto was the default only for Pro/Max/Team with feature flags (2.1.228+). Feed dates: 2.1.283 = 2026-09-25, 2.1.288 = 2026-10-02. This is the strongest data point for the owner's thesis.
2. **Codex retired `untrusted` and deleted the known-safe command allowlist on 2026-08-20** (commit `942af8447b`, "Retire the untrusted approval policy (#39630)"), four days before the baseline. The baseline's "untrusted projects only auto-approve known-safe read commands" is stale. Explicit `approval_policy = "untrusted"` now errors (`core/src/config/mod.rs:3739`). `UnlessTrusted` survives only as an internal value for projects marked untrusted, and it prompts for every command not matched by an exec-policy rule (`core/src/exec_policy.rs:795-800`). Also `on-failure` is now only a serde alias for `on-request` (`protocol/src/protocol.rs:1000`), not a separate deprecated mode.
3. **Codex reviewer default is `user`** (`protocol/src/config_types.rs:183-190`). The `guardian_approval` feature is Stable and default-enabled (`features/src/lib.rs:1709`), which only makes the reviewer available. The config value `guardian_subagent` is a legacy alias for `auto_review`.
4. **Gemini does have an LLM checker**: Conseca (`security.enableConseca`, default `false`; `policies/conseca.toml` registers a `safety_checker` on `*`). The baseline's "no separate reviewer" is true only by default.
5. Pi is now 1.0.0 and has **project trust** (gates loading of `.pi/*` resources, not tool calls). The core still has no approval prompt.

## Claude Code

- **Default**: `auto` (classifier). It falls back to Manual when auto is unavailable: unsupported model, `disableAutoMode`, or a server-side kill switch. `claude -p`/SDK start in `default` when feature flags are fetched, and in `auto` when they aren't (2.1.285+).
- **Modes**: `default` (labelled "Manual", alias `manual`), `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`. Shift+Tab cycles default → acceptEdits → plan, with auto and bypass slotted in after. `dontAsk` is never in the cycle.
- **What runs without asking**:
  - `default`: reads and a built-in read-only bash set (`ls cat echo pwd head tail grep find wc which diff stat du cd`, read-only `git`). The set isn't configurable. Unparseable commands, unquoted globs with write-capable flags, `cd`+`git`, and commands over 10k characters prompt (https://code.claude.com/docs/en/permissions).
  - `acceptEdits`: in-scope file edits plus `mkdir touch rm rmdir mv cp sed`, including with safe env or `timeout/nice/nohup` prefixes. Other bash prompts.
  - `auto`: everything not decided by a rule goes to the classifier. Order: allow/ask/deny rules first, then read-only actions and in-cwd edits auto-approved, then the classifier.
  - `dontAsk`: anything that would prompt is denied.
  - `bypassPermissions`: everything except "actions no mode auto-approves": ask rules, `AskUserQuestion`, and critical-path `rm`/`rmdir`.
- **Classification**: shell-aware rules. Compound commands are split and each part must match. Fixed wrapper stripping (`timeout time nice nohup stdbuf command builtin`). Docs say Bash rules are "not a security boundary" (`/usr/bin/curl`, `sh -c` bypass them).
- **Auto classifier**: a model reviews actions. Server-side review is the default on a direct API connection (2.1.271–282). The client-side classifier is a fallback and may be billed. It has a default block list: `curl|bash`, force-push, prod deploy, mass cloud deletes, IAM grants, secret exfiltration, etc. Admins extend it with `autoMode.environment`. On entering auto it drops broad allow rules (`Bash(*)`, `Bash(python*)`, `Agent`). Boundaries stated in conversation count as block signals. Fallback: 3 consecutive or 20 total blocks pauses auto and resumes prompting. In `-p` with no prompt tool, the action is simply denied and the run continues. Critical-path `rm` gets a 2-minute prompt, then a deny with a rewrite hint (changelog 2.1.281 region).
- **Sandbox**: exists and is **off by default**. OS-level (Seatbelt on macOS; bubblewrap + socat on Linux/WSL2; none on native Windows) via `@anthropic-ai/sandbox-runtime`; enabled with `/sandbox` or `sandbox.enabled`. Defaults: writes to cwd + temp dir + added dirs; reads of most of the machine (including `~/.ssh`); no direct network, only a proxy with an empty allowed-domain list. Only Bash/PowerShell/Monitor are covered. File tools, MCP and hooks run outside it (https://code.claude.com/docs/en/sandboxing). Two sandbox modes: **auto-allow** (sandboxed commands run without prompting, independent of permission mode) and regular permissions. Escape hatch: an unsandboxed retry (`dangerouslyDisableSandbox`) prompts in Manual/acceptEdits and is classified in auto. `allowUnsandboxedCommands:false` is strict mode. If dependencies are missing it silently runs unsandboxed unless `failIfUnavailable` is set.
- **Prompt UI**: Yes / "Yes, and don't ask again for: `npm test *`" / "Yes, and switch to auto mode" (when available) / No; Tab adds a comment. The "don't ask again" rule is saved to `.claude/settings.local.json` at the repo root. File-edit approvals last until session end. Per-command saved rules are therefore still a live, central feature, though auto is the new default.
- **Status bar**: `⏸ manual mode on`, `⏵⏵ accept edits on`, `⏸ plan mode on`, `⏵⏵ auto mode on`, `⏵⏵ don't ask on`, `⏵⏵ bypass permissions on`. A first-run notice explains the auto default.
- **Headless**: `-p` with `--permission-mode dontAsk --allowedTools ...` for CI. Unanswerable prompts are denied, never silently allowed.
- **Since 2.1.268 (≈2026-09-10)**: auto as built-in default; server-side classifier default; per-command `allowed_domains` for sandboxed commands in auto (2.1.271); `blockReadsOutsideWorkingDirectories` (2.1.257); the "switch to auto mode" prompt option (2.1.247). 2.1.285 made project settings unable to widen or disable an admin-required sandbox. `auto` and `bypassPermissions` are ignored as `defaultMode` from project `.claude/settings*.json` (repo-provided config can't grant autonomy; relevant to the cohesive approval design provenance point).

## Codex CLI

- **Default (new user)**: without a project-trust decision, `approval_policy=on-request` with `sandbox_mode=read-only` (`SandboxMode` `#[default] ReadOnly`, `protocol/src/config_types.rs:104-107`; `AskForApproval` `#[default] OnRequest`, `protocol.rs:998`). Trusted project: `on-request` + `workspace-write`. Untrusted project: internal `UnlessTrusted` (prompt everything) + `workspace-write` (`core/src/config/mod.rs:3748-3757`; `config/src/config_toml.rs:850-860`). Windows without the sandbox forces read-only. Trust prompt strings were not extracted.
- **Axes**: approval policy (`on-request`, `granular{sandbox_approval, rules, skill_approval, request_permissions, mcp_elicitations}`, `never`, plus internal untrusted), permission profile (`:read-only`, `:workspace`, `:danger-no-sandbox`, or custom `[permissions.*]`), and reviewer (`user` | `auto_review`). Built-in TUI presets (`utils/approval-presets/src/lib.rs`): **Read Only** (on-request + read-only), **Default** (on-request + workspace-write), **Full Access** (never + no sandbox). A fourth, "Approve for me", is Default plus the auto_review reviewer (`tui/src/app.rs:424`). CLI flags: `--approve-for-me` (alias `--not-so-yolo`), `--dangerously-bypass-approvals-and-sandbox` (alias `--yolo`).
- **Classification** (`core/src/exec_policy.rs:770-855`): Starlark exec-policy rules (`prefix_rule`, `allow|prompt|forbidden`; `~/.codex/rules/default.rules` plus managed overlays) are checked first. For unmatched commands: a dangerous match (`rm -f`/`--force`, unwrapped through `sudo`, `env`, `trap`, `bash -lc` literals, depth-capped at 8 and failing closed; Windows has a larger list) → Prompt (or Forbidden under `never`). Otherwise `never` → Allow and rely on the sandbox; `UnlessTrusted` → Prompt; `on-request` with a restricted filesystem → **Allow unless the call asks for a sandbox override**, i.e. the sandbox is the gate rather than a command allowlist; `on-request` with an unrestricted/external sandbox → Allow. Commands bypass the sandbox only if every segment matches an explicit allow rule. Changes since August: git no longer inherently safe (#39524, 08-19) and dynamic shell words require approval (#39159, 08-18).
- **Sandbox**: Linux uses bubblewrap by default (system `bwrap`, else bundled), with `PR_SET_NO_NEW_PRIVS` and a seccomp network filter. Legacy Landlock is **rejected** for filesystem-restricted policies (`linux-sandbox/README.md`). macOS uses Seatbelt (`sandboxing/src/seatbelt*.sbpl`). Windows has a native/MXC sandbox. `workspace-write` = `/` read, project roots + `/tmp` + `$TMPDIR` + extra roots write, with `.git`, `.agents`, `.codex`, `.aws` re-bound read-only (`protocol/src/permissions.rs:819-873`). Network is **restricted by default** (`--unshare-net`; `NetworkSandboxPolicy::Restricted`); `sandbox_workspace_write.network_access=true` or a managed proxy opens it.
- **Escalation prompt** (`tui/src/bottom_pane/approval_overlay.rs`): "Would you like to run the following command?" + Reason. Options: "Yes, proceed" / "Yes, and don't ask again for commands that start with `<prefix>`" (writes an exec-policy amendment) / "Yes, and don't ask again for this command in this session" / "No, continue without running it" / "No, and tell Codex what to do differently". Network prompts offer once, this conversation, and allow/block host in future. Permission grants offer this turn, "this turn with strict auto review", or this session.
- **Auto-review (guardian)**: a sandboxed subagent reviews approval requests (sandbox escapes, network, MCP, etc.), with `REVIEW_TIMEOUT` = 90 s (`ext/guardian-reviewer/src/lib.rs:41`). Errors fail closed (`guardian/review_session_context.rs:77`). Denials are listed in the TUI ("Auto-review Denials"). Guardian V2 is being iterated heavily (async classification, a "Decisions" comparison harness, history retention). The TUI says "We strongly recommend selecting 'Approve for me'" when users pick Full Access (`permission_popups.rs:443`). Default reviewer stays `user`.
- **Headless**: `codex exec` sets `approval_policy=Never` by default (`exec/src/lib.rs:589-591`), so sandbox read-only by default; dangerous commands become Forbidden rather than prompting.
- **Status**: `/status` "Permissions" shows `Read Only (Ask for approval)`, `Workspace (Ask for approval)`, `Workspace (Approve for me)`, `Full Access`, `Custom (...)`. A status-line item exists for approval mode. Ask for approval = on-request + user reviewer.
- **Since 08-24** (`git log`): permissions made server-authoritative in the TUI (#49472, #50140), projectless sessions get workspace defaults (#49160), grants bound to originating turn (#49880), `.aws` protected (#48176), approved filesystem escalation keeps denied reads (#49353), Windows MXC sandbox wired in.

## Gemini CLI

- **Default**: `default`. If the folder is untrusted, any other mode is forced back to `default` (`packages/cli/src/config/config.ts:759-764`). The sandbox is off by default.
- **Modes** (`core/src/policy/types.ts:48`): `default`, `autoEdit`/`auto_edit`, `plan`, `yolo`. Indicator text: "auto-accept edits", "plan", "YOLO" (red), and in default mode only a cycle hint (`ApprovalModeIndicator.tsx`). Shift+Tab cycles default/autoEdit/plan; YOLO has a separate toggle. `security.disableYoloMode` and `admin.secureModeEnabled` can disable YOLO.
- **Default policy** (`policies/*.toml`): read tools, `grep_search`, `read_file`, `list_directory`, `google_web_search`, etc. are allow@50. `write_file`, `replace`, `run_shell_command`, `activate_skill` are ask_user@10 (interactive only). autoEdit allows `write_file`/`replace` @15, gated by an `allowed-path` safety checker. YOLO allows `*`@998, but `ask_user` stays prompted and plan transitions are denied.
- **Shell classification** (`policy-engine.ts:365-445`, `sandbox/utils/commandSafety.ts`): `applyShellHeuristics` escalates to ASK_USER for cwd outside the workspace, git in untrusted folders, or a dangerous command. It **upgrades ASK_USER→ALLOW for a known-safe command**, a strict allowlist (`cat cut echo expr grep head id ls nl paste pwd rev seq stat tail tr uname uniq wc which whoami tac numfmt cd ...`) with per-tool deep checks for `find`, `rg`, `git`, `sed`, `base64`, and `bash -c` bodies that block `()<>`. Compound commands are split per segment, and redirection downgrades ALLOW→ASK. This allowlist is applied regardless of sandbox. Workspace-tier policy files are documented as **non-functional** (issue #18186); user and admin tiers work.
- **Sandbox** (https://geminicli.com/docs/cli/sandbox, `docs/cli/sandbox.md`): opt-in via `-s`, `GEMINI_SANDBOX`, or `tools.sandbox`. Options: macOS Seatbelt (default profile `permissive-open`: writes confined to the project, network allowed), Docker/Podman (cwd mounted at the same path), Windows native (icacls low-integrity), gVisor/runsc, and LXC. Tool-level sandboxing (`security.toolSandboxing`, default `false`, with bwrap and seatbelt managers in `core/src/sandbox/`) comes with **"Sandbox Expansion Request"** dialogs that approve extra paths or network per run.
- **Reviewer**: none by default; Conseca LLM checker behind `security.enableConseca` (default false).
- **Prompt UI**: Allow once / Allow for this session / Allow for all future sessions (persisted as a mode-aware user-tier rule; approvals in `plan` apply to all modes, otherwise to the current mode and more permissive ones).
- **Headless**: ask_user decisions become **deny** (`policy-engine.ts:301`); `ask_user` tool is denied; `--approval-mode`, `--yolo` (deprecated) apply.
- **Since 08-24**: stable v0.61.0 (09-23): prompt-injection defence for build-file modifications and untrusted flags, sandbox boundary hardening. Preview 0.63.0 (09-29): autonomous plan execution in non-interactive mode, policy redirection-gate alignment. No default-mode change.

## Pi (pi-mono)

- **Default**: no approval concept. Default tools `read, bash, edit, write` run directly (`docs/settings.md` `defaultTools`). `docs/security.md`: Pi "does not ask for approval before every tool call" and "lack of a built-in sandbox" is outside the security boundary.
- **Modes**: none. Tool-name allowlists via `--tools`/`--no-tools`/`defaultTools`, with `+name`/`-name` entries (0.99+). Project trust (`defaultProjectTrust`: `ask|always|never`, saved in `~/.pi/agent/trust.json`, `/trust`, `--approve`/`--no-approve`) gates loading of `.pi/settings.json`, extensions, skills, and `mcp.json`. Print/JSON/RPC modes skip protected resources unless trust is `always`.
- **Gating** is done by extensions through the `tool_call` hook (`examples/extensions/permission-gate.ts`, which blocks `rm -rf`/`sudo`/`chmod 777` by regex and blocks outright without a UI; also `protected-paths`, `plan-mode`, `confirm-destructive`).
- **Isolation**: documented as a deployment choice (Docker, Docker Sandboxes, OpenShell, Gondolin micro-VM extension; `docs/containerization.md`). The new built-in `codemode` runs model JS in QuickJS with no fs/network, reaching the world only through tools (0.99.0, 2026-09-29). It is an interpreter sandbox for scripts, not for `bash`.
- **Since 08-24**: 0.99.0 (codemode, MCP, tool_search), 1.0.0 (fullscreen TUI default). No approval changes.

## Cross-harness observations for the cohesive approval design

- Every harness that restricts at all pairs auto-execution with **either** an OS sandbox (Codex: allow-by-default inside workspace-write; Claude sandbox auto-allow; Gemini opt-in) **or** a model classifier (Claude auto, Codex auto_review). Only Gemini's known-safe list and Claude's read-only set are pure command-text allowlists, and both are short, read-only, and path-checked.
- Codex deleted its read-only command allowlist (08-20) in favour of "sandbox is the gate + explicit exec-policy rules + dangerous-command prompt". Claude and Gemini retained theirs.
- Default posture trend: Claude moved from Manual to **auto**. Codex stays on-request but the sandbox makes most commands prompt-free; Read-only is the true cold default until trust is granted. Gemini remains prompt-for-writes/shell. Pi never prompts.
- Repo-provided config is deliberately denied autonomy-granting power in Claude (`auto`/`bypass` ignored from project settings) and Gemini (workspace policies disabled; untrusted folder forces `default`); Codex keys trust in user config (`[projects."<path>"]`).
- Headless: Claude `dontAsk`/deny, Gemini deny, Codex `never` (sandbox bounds, dangerous Forbidden). None silently allow.
- Not verified: Codex trust-prompt wording; Gemini footer text in default mode beyond the indicator source; Claude classifier false-allow/deny rates (no primary data published in the docs read).
