# Headless Startup-to-Interactive Baseline — 2026-04-27

## Summary

This report records the first startup-oriented measurement path for yach. It measures a narrow backend-ready-to-first-interactive boundary using the headless benchmark seam, not a live terminal.

**Measurement class:** headless proxy / component evidence.

The PRD target is startup to interactive prompt `<250 ms after backend ready`. This benchmark exercises the same conceptual interval in a synthetic headless harness, but it does not include live terminal draw/flush, real backend process behavior, or OS input event delivery. Treat it as methodology scaffolding and component baseline, not final PRD-facing evidence.

## Timing boundaries

`t0_backend_ready` starts immediately after the benchmark creates a `BenchmarkApp` and applies the synthetic connected event. The timer begins before applying the synthetic backend-ready state update.

`t1_interactive` stops after:

1. applying `ready_state_event()`;
2. rendering the first backend-ready app state into a ratatui `TestBackend` buffer;
3. applying a synthetic `x` keypress to prove prompt input can mutate;
4. rendering the post-keypress app state into the same headless buffer size.

Included:

- app state update for backend-ready state;
- first render after ready;
- one prompt-mutating keypress;
- render after the keypress.

Excluded:

- process launch;
- adapter/backend initialization;
- Pi RPC transport;
- model/auth setup;
- live terminal draw/flush;
- terminal emulator paint;
- OS input event delivery.

## Claim supported

This report supports a limited component-level claim:

- A repeatable backend-ready-to-first-interactive measurement path exists.
- In headless proxy measurement on this machine, applying a ready state, rendering, accepting one keypress, and rendering again is sub-millisecond.

## Confidence and limitations

- **Confidence:** Useful as a regression baseline for the benchmark seam and the app/render work that happens after backend-ready state is available.
- **Limitations:** Does not prove the PRD `<250 ms` startup SLO in a live terminal. The excluded terminal/backend/PTY phases are likely the important parts of user-perceived startup.
- **Sample count:** 30 Criterion samples. This report does not claim p95/p99 startup latency.

## Follow-up
