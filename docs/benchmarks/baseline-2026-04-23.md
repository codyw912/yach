# Baseline Benchmarks — 2026-04-23

Machine: Apple Silicon (aarch64-apple-darwin), release profile.
Criterion 0.5.1, plotters backend.

## Protocol Parsing

| Benchmark | Time |
|---|---|
| `parse/single_delta` | 204 ns |
| `parse/server_event_from_json` | 201 ns |
| `parse/1000_delta_lines` | 202 µs |
| `parse/1000_status_lines` | 179 µs |
| `parse/1000_tool_call_lines` | 177 µs |
| `parse/500_mixed_stream` | 114 µs |

**Interpretation:** ~200 ns per line parse. 1000 lines in ~200 µs means ~5M lines/sec throughput.

## Transcript

| Benchmark | Time |
|---|---|
| `transcript/1000_append_deltas` | 42.1 µs |
| `transcript/100_large_deltas` (10KB each) | 20.6 µs |
| `transcript/500_alternating_entries` | 29.0 µs |
| `transcript/200_tool_call_entries` | 49.5 µs |
| `transcript/1000_with_compactions` | 46.0 µs |
| `transcript/content_render_500_entries` | 82.0 µs |
| `transcript/compaction_count_1000` | 5.45 ns |

**Interpretation:** Appending 1000 deltas takes 42 µs. Building a 500-entry transcript and rendering to string takes 82 µs.

## Summary

The protocol layer is fast enough that it will never be the bottleneck. Even at 1000 events/sec (far beyond any realistic Pi stream rate), dispatch takes ~40 µs total. The serialization layer is similarly fast. The transcript append cost is the most expensive single operation but still sub-50 µs for 1000 deltas.

What to measure next:
- Startup time (process launch → first frame)
- Input-to-first-token latency (keypress → transcript update)
- Render latency per frame
- Memory footprint at idle and under load
- Large transcript handling (10K+ entries)
