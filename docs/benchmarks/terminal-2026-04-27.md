# Live Terminal Startup/Draw Baseline — 2026-04-27

## Summary

This report records the first live Crossterm terminal draw/flush measurement for yach's benchmark harness. It measures a narrow backend-ready-to-first-interactive path in a real TTY using `ratatui::CrosstermBackend`, raw mode, and the alternate screen.

**Measurement class:** live terminal.

This is closer to PRD-facing startup evidence than headless proxy measurements because it includes terminal backend drawing/flushing. It is still synthetic: it does not include process launch, real backend/Pi RPC startup, auth/model setup, or OS event delivery for a real human keypress.

## Timing boundaries

`t0_backend_ready` starts after the benchmark creates a `BenchmarkApp`, applies the synthetic connected event, enters raw mode / alternate screen, and creates a live `CrosstermBackend` terminal. The timer begins before applying the synthetic backend-ready state update.

`t1_interactive` stops after:

1. applying `ready_state_event()`;
2. rendering the first backend-ready app state to a live Crossterm terminal;
3. applying a synthetic `x` keypress directly to the app to prove prompt input can mutate;
4. rendering the post-keypress app state to the live Crossterm terminal.

Included:

- app state update for backend-ready state;
- ratatui rendering through `CrosstermBackend`;
- terminal draw/flush work performed by the backend;
- one prompt-mutating synthetic keypress;
- render after the keypress.

Excluded:

- process launch;
- adapter/backend initialization;
- Pi RPC transport;
- model/auth setup;
- real OS keyboard event delivery;
- terminal emulator presentation timing beyond the backend draw/flush boundary.

## Claim supported

This report supports a narrow live-terminal claim:

- On this machine and terminal environment, the synthetic backend-ready-to-usable-input path including live Crossterm draw/flush is well below the PRD `<250 ms after backend ready` startup target across 20-, 100-, and 1,000-sample runs.
- The 1,000-sample run gives a stronger tail baseline: p95 2.115 ms, p99 2.496 ms, max 8.187 ms.

## Confidence and limitations

- **Confidence:** Useful first live-terminal evidence for post-backend-ready TUI responsiveness. Includes real terminal backend draw/flush, unlike headless proxy reports.
- **Limitations:** Synthetic keypress is injected directly into app logic rather than delivered through OS/crossterm event polling. Does not include backend/Pi startup, process launch, auth/model setup, or transport.
- **Outliers:** Max values remained below 10 ms across the recorded runs. The 1,000-sample run had p99 2.496 ms and max 8.187 ms, which is a stronger tail signal than the initial 20-sample run.
